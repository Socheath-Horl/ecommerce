01 · Foundations

Tokens, named and paired for both themes.

Every color is a CSS variable. Dark mode inverts background, foreground, and primary wholesale; the status set raises luminance. Values below are copied from system-ui-design.md §2.1.

background

App background — forces the 1px border on every surface.

surface

Cards, modals, drawers, raised surfaces.

foreground

Default text, headings, icons.

muted

Secondary text, placeholders, captions.

border

Inputs, table rows, card hairlines.

primary

Buttons, active nav, links. Inverts with theme.

primary-foreground

Text on primary — always the opposite of primary.

hover-fill

secondary · muted · accent-hover — chips, zebra, skeletons.

05 · Components

The building blocks, live.

Each sample renders with the tokens above, including hover, focus, and disabled states. The full composition tree lives in system-design.md §5.

Buttons

Hover and :focus-visible are defined studio-wide. Disabled is the only state allowed to lower contrast. At most one primary-styled button per action.

Fields

Focus ring = 2px accent on transparent tint; label ≥ 44px hit via field padding; validation errors return inline field errors + toast per §5.2.

Badges & tags

06 · Accessibility

A contract, not a wishlist.

Every screen in the app ships against these three rules — system-ui-design.md §2.4.

Touch & hit targets

Every target ≥ 44px — buttons, steppers, icon-only controls (cart, theme, close), menu rows. No exception for "small" controls.

Focus & keyboard

A visible :focus-visible ring on every control. Drawers open on Enter/Space, close on Esc with focus returning to the trigger; selects and star rating are keyboard-operable.

Contrast & color

Hover/focus/selected flip bg + fg together and never drop below 4.5:1 text / 3:1 icons. Color is always paired with a text label — never the only signal.
