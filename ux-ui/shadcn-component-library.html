Component blueprints, based on shadcn/ui.

We adopt shadcn/ui’s architecture — Radix primitives, compound parts, data-attributes, and a class-variance-authority variant API — while keeping our own brand tokens, serif display face, and accessibility contract. shadcn/ui’s model, not its skin.

01 · The rebase

Every visual becomes a shadcn/ui component.

Three rules govern the translation so the React app stays ungated: name it like shadcn/ui, drive behavior with Radix, and keep styling a function of variant + size.

Adopt the API, not the wardrobe

shadcn/ui defines the names, parts, and props; we override the classes and tokens. Button = props, so code review reads imports, not inline styles.

Radix under every hood

Interactive primitives are Radix primitives. Styling keys off data-state and data-disabled — never off class-name hacks — so keyboard + ARIA come for free.

Variants & sizes are data

Class Variance Authority turns variant + size into a closed set of states. New styling always extends the matrix — never forks the component.

06 · Dark bridge

shadcn/ui class strategy over our OKLch tokens.

Tailwind runs with darkMode: ['class']: the toggle flips html.dark, CSS variables swap wholesale, and every component re-colors with zero per-component overrides.

Loader

// init.ts — same key as the design files
const t = localStorage.getItem('ui.theme') ??
matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
document.documentElement.classList.toggle('dark', t === 'dark')
// color-scheme + Tailwind dark: variants both react to html.dark

First paint is controlled by an inline script (no FOUC); the toggle persists back to ui.theme so the design files and the app stay in sync.

07 · Usage

From blueprint to the registry.

shadcn/ui is the component model; this page is the contract it must satisfy. When you scaffold, the mapping above is the inventory — the dark bridge is the config.

Primitives first

Every screen is assembled from the primitives above — no bespoke control for a bespoke need. Custom pieces (stepper, MultiUpload) stay local.

Registry discipline

Tokens live in globals.css as CSS variables; components.json tracks the registry; variants extend cva, never fork a file.

Accent budget

Two accents a viewport, max. Status colors stay in Badges; primary buttons stay the single call to action per action group.

Two references, one system.

component-library.html owns the visuals and interactions; this blueprint owns the shadcn/ui mapping, parts, and data-attributes. Screens are composed from the second against the first.
