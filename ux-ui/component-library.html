02 · Actions

One primary per action, every state accounted for.

Buttons, icon controls, chips, tags, and pagination — hover and :focus-visible defined studio-wide; disabled is the only state allowed to lower contrast.

Buttons

Danger is outline so destructive text never sits on the near-black primary. Loading swaps a placeholder for the spinner (border-right transparent) on currentColor.

Icon controls

Every icon target is 44×44 — no exception. Hairline variants sit on chrome; bordered variants claim space on surfaces.

Status chips · tags

Status = color dot + text label, never color alone. Tags are neutral hover-fill; the pill is accent-tinted and reserved for promoted flags.

03 · Forms

Fields with inline errors, not apologies.

Every control keeps a ≥44px hit target, a visible focus ring, and never reads color alone — error text pairs with a glyph.

Fields

Focus = 2px accent-soft ring + border swap. The password toggle lives inside the control at 44px without leaving the field’s hit area.

Validation · error state

Max price is below the min price.

Inline error = destructive border + ! glyph + message. Destructive raises luminance in dark so the 13px text keeps 4.5:1 on every surface.

Checkbox · radio

Native inputs with accent-color keep all keyboard + assistive-tech behavior for free. Labels sit beside the control for ≥44px rows.

04 · Feedback

Confirm before you destroy, toast after.

Destructive actions always confirm via dialog; transient results surface as toasts; carts and empties have their own surfaces.

Toast

Live toasts stack bottom-right and auto-dismiss after ~4s. Success/Info use role=status; error uses role=alert. Message copy stays short — details live in the page.

Confirm dialog

Dialog opens on Enter/Space from the trigger and closes on Esc with focus returning to that trigger. The destructive action inside is a real outline .btn-danger — never a disabled-looking gray.

Cart drawer

Drawer slides from the right and closes on overlay click or Esc. “Clear cart” inside demos the empty state; “Add to cart” bumps the header badge and restores the list.

07 · Usage

Tokens → components → screens.

Three rules keep the library coherent: one artifact per concern, tokens never hard-coded, and no more than two accents a viewport.

Start from tokens

brand-spec.md owns the six OKLch tokens and their dark pairs. Every component here renders them — no raw hex anywhere outside :root.

Pair with the DS

This library is the live spec; ecommerce-design-system.html holds the foundations, status mapping, type ramp, and a11y contract it obeys.

Two accents, max

Accent appears at most twice per viewport; status colors stay inside their chips; everything else runs on bg / surface / fg / muted / border.

Locked. Screens next.

The screens — Home, Product, Cart, Checkout, Orders, Admin — each begin as compositions of these blocks, then translate to Penpot and into React (shadcn/ui).
